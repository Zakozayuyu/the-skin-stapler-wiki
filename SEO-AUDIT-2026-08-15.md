## New Findings (this round)

### P1 — Add `og:image` to the 35 article/pillar pages (recommended, low risk)

Every English and localized guide, walkthrough, ending, and wiki page ships an `image` in its `Article`/`CollectionPage` JSON-LD, but **no `og:image` meta tag**. Cause: the root layout defines a global `openGraph.images` (hero.jpg), but the six page-level metadata builders override `openGraph` with title/description/url/type and no `images` field, so the inherited image is dropped.

Affected metadata builders:

- `src/app/walkthrough/page.tsx`
- `src/app/ending/page.tsx`
- `src/app/wiki/page.tsx`
- `src/app/guides/[slug]/page.tsx`
- `src/app/[locale]/[pillar]/page.tsx`
- `src/app/[locale]/guides/[slug]/page.tsx`

Fix: each of these pages already selects an `ArticleImageKey` from `src/lib/article-media.ts` (used for the Article schema image and the in-page figure). Add the same image to `openGraph.images` with its known `width`/`height` and a localized `alt`, e.g. `images: [{ url: articleMedia[image].src, width: articleMedia[image].width, height: articleMedia[image].height, alt: articleMedia[image].description[locale] }]`. Images are 1440×810 WebP (~1.78:1) — close to the 1200×630 recommendation and fine for large-card shares. Impact: social/chat scrapers (X, Discord, Facebook) currently show no image for the site's most-linked pages.

### P2 — `og:url` missing on 17 pages (recommended, low risk)

Homepage, `/guides`, `/guides/beginner`, localized homepages, localized hubs/legal pages, and the two 404 documents have no `og:url` (article/pillar pages have it). Fix: add an absolute `url` (resolved by `metadataBase`) to the `openGraph` of the owning pages. Where a page sets no `openGraph` at all, add one with the canonical URL.

### P3 — Localized pages ship `<html lang="en">` (medium)

All 33 `/{de|es|pt-br}/...` documents render `<html lang="en">` in the raw HTML. `src/app/layout.tsx` hardcodes `lang="en"` and patches it at runtime with an inline script. `og:locale` is correctly set on localized article/pillar pages, and hreflang is correct, so search impact is limited — but the raw HTML is wrong for non-JS crawlers, screen readers that read static HTML, and language heuristics.

Proper fix (structural, schedule separately): split the app into locale route groups `app/(en)/…`, `app/(de)/…`, `app/(es)/…`, `app/(pt-br)/…`, each with its own root layout carrying the correct `lang` (URLs unchanged). Verify against the Next 16 docs in `node_modules/next/dist/docs/` before writing it (per `AGENTS.md`, this repo uses Next.js 16 with breaking changes). Do not attempt this in the same round as other changes; verify build, sitemap, canonicals and hreflang output after.

### P4 — 404 pages duplicate the homepage title (minor)

`404.html` and `_not-found.html` carry the homepage title "The Skin Stapler Wiki — Walkthrough, Puzzles & Endings" and no canonical. They are already `noindex`. Fix: export metadata from `src/app/not-found.tsx` with a distinct title (e.g. "Page Not Found | Skin Stapler Wiki") and keep `robots: { index: false }`.

### P5 — Short meta descriptions on hubs, beginner and legal pages (minor)

Below the 120–160 char standard: `/guides` (94), `/guides/beginner` (92 de / 84 es / 85 pt-br), `/{locale}/guides` (83–98), and all privacy/terms pages (41–49). Legal page content is protected, but metadata text is safe to extend with a sentence of plain-language scope. Optional polish.

### P6 — Homepage OG image is 460×215 (minor)

`hero.jpg` (460×215) is the global OG fallback and homepage share image — under the 1200×630 standard, so shares render small. Optional: add a dedicated 1200×630 share image in `public/` and reference it from the root layout.

### P7 — FAQ content exists but no `FAQPage` schema (optional, low priority)

Walkthrough and Ending pages have visible FAQ sections (4 questions each) without `FAQPage` JSON-LD. Google now shows FAQ rich results only for authoritative health/government sites, and the standard requires 5+ questions, so the ROI is low. Either add a fifth question + matching `FAQPage` on the walkthrough, or keep the current "no decorative schema" policy. Not recommended this round.

### P8 — `og:locale` absent on localized hub/home/legal/beginner pages (minor)

Article and pillar pages set `og:locale` (de / es / pt-br); localized homepages, hubs, beginner and legal pages do not. Add `locale` to their `openGraph` when touching P2.

### Deliberate deviations from the skill standard (documented, keep)

- **No trailing slash on canonicals/URLs** — established site policy, consistent across all 55 pages, self-referencing, and protected by the 2026-08-13 audit. Changing now risks winner URLs for zero gain.
- **Sitemap priority 0.8 for legal pages** (standard suggests 0.3) — cosmetic, keep.
- **`meta name="keywords"` with 2–4 terms** instead of 10–15 — Google ignores this tag entirely; negligible.
- **Site-wide `WebSite`/`Organization`/`VideoGame` JSON-LD graph on every page** — factual and consistent; no action.
- **`redirects()`/`headers()` in `next.config.mjs` are inert under `output: 'export'`** — known limitation; `public/_headers` already covers the security headers on Cloudflare Pages.

## Automated Script Results (with false-positive notes)

`seo-auditor/resources/audit_rules.js` scores: `index.html` 68/D, `walkthrough.html` 80/B. Most deductions are tooling artifacts, not site defects:

- **"Missing H1" on homepage** — false positive: the regex requires plain text inside `<h1>`; the site's H1 contains `<br/>` and `<em>`.
- **"No JSON-LD found" on every page** — the script only reports schema whose top-level object has `@type`; this site's JSON-LD is a `@graph` with no top-level `@type`, so all 96 blocks are silently skipped.
- **"External links missing rel=noopener"** — false positive: links use `rel="noreferrer"`, which implies noopener in all modern browsers.
- **"OpenGraph incomplete" on homepage** — accurate: `og:url` is genuinely missing (see P2).
- The script's 50-char description minimum and 10-15 keyword expectation also diverge from what matters in production; treat its score as directional only. Suggested script fixes if reused: allow nested markup in H1, walk `@graph` nodes, accept `noreferrer`, check `og:url` explicitly.
